## Fixes and deterministic evidence

The former `.ctx-repair-lock.reclaim` directory could survive owner death and block all future repair. The new gate holds a native-independent SQLite `BEGIN IMMEDIATE` write transaction for the entire asynchronous callback. Failure-marker checks and writes happen while holding it; `ROLLBACK` and connection close release it. The database is never unlinked. OS process death releases its lock; there is no lease-based stealing or PID reuse decision.

The statistics path now opens a fresh readonly transaction on every call. Filesystem memoization and append-only deltas are removed: neither file metadata nor one row's identity proves that older aggregate fields were not updated. A failed `BEGIN` skips that sidecar instead of mixing statement snapshots. This intentionally gives up the previous warm-read optimization; it does not hide stale values behind a TTL.

The identical initial 13-case fixture failed five assertions before the fixes and passed all 13 afterwards. Enhanced actual-12.9.0 acceptance passed all 19 cases: highest and older-row WAL aggregate UPDATEs, earliest time, UPDATE+INSERT, uncommitted writes, commits between aggregate queries, failed BEGIN, deletion/replacement, dead reclaim residue, live-owner exclusion, failure backoff, changed ABI key, owned hard-kill recovery, state-unavailable recovery, corrupt failure state, and Node/Bun mutual exclusion in both directions. Eight existing affected tests in two files also passed, serially. Independent review found no new P0/P1/P2 in these fixes under the quiescent-upgrade premise.

## Current acceptance and remaining limits

- Official locked native binding actually loads on the current Windows host.
- Complete isolated `start.mjs` cold / first-warm / steady-warm: relative Chinese index, search, normal execution, exit 37 and EOF exit 0 passed. Initialization was about 2.65 / 2.79 / 2.51 seconds. Cold startup seeds the ABI cache; first warm startup performs one swap/stamp setup; steady warm startup performs zero native copies. No install/rebuild occurred. Runtime-discovery probes still run, so the whole startup is not constant-time or probe-free.
- Warm lifetime statistics on 24 synthetic DBs × 1000 rows × 256-byte payload: before median about 0.61 ms; after about 27.65 ms with the same official native binding. This is a deliberate correctness tradeoff. Earlier builtin-SQLite 5.4 ms cache figures are historical and no longer describe this candidate.
- **Failed actual orphan case:** parent exits first while a detached child holds inherited output pipes. MCP/executor cancellation settles after termination grace, but the child remains alive. The test cleaned only its recorded owned child afterwards. Bounded settlement is not proof of descendant termination.
- **Host death during installation remains a deployment boundary:** a killed mutex owner may leave npm/heal descendants modifying files while a new owner acquires the now-free SQLite lock. The simple callback-owner crash test does not prove installer-tree safety. Exported direct repair calls and postinstall heal entry points are not unified by this gate.
- **Quiescent upgrades are mandatory:** the old directory gate and new SQLite gate are different protocols. Do not mix them concurrently against one installation root. Old residue is ignored, not removed or stolen.
- Early Node 22.5 needs `--experimental-sqlite` for `node:sqlite`; unavailable builtin support returns `state-unavailable`, never an unlocked repair. Bun uses `bun:sqlite`. New compatibility acceptance here covers current Node24 and Bun1.4.2; it does not re-certify all Node22 releases.
- **Chinese cleanup root-cause assessment:** current Node24.13.0 `rmSync` silently leaves fresh Chinese paths, including namespaced paths; `unlinkSync` + `rmdirSync` works in the same ordinary token. Its native source constructs `std::filesystem::path` from a narrow string. The upstream Unicode defect is documented in [Node issue #56049](https://github.com/nodejs/node/issues/56049); [this exact runtime source](https://github.com/nodejs/node/blob/v24.13.0/src/node_file.cc#L1500) still contains that conversion. The root-cause assessment is an inference consistent with those sources and direct controls, not an instrumented native-debugger trace. No Node upgrade, global UTF-8 setting, ACL change, or executor cleanup workaround was deployed.
- **cmd controls:** `C:/Windows/System32/cmd.exe` itself fails even `echo OK`; the same executable spelled with backslashes succeeds. Embedded command quotes also require correct Windows argument handling. These are isolated real-subprocess controls, not inferred from mock tests.
- Windows tree termination is synchronous with a 5-second taskkill cap, followed by a 1.5-second settlement grace; this is not a 1.5-second total SLA. Existing Rust compilation remains synchronous and cannot process MCP cancellation while blocked.
- The configured host plugin path, native file and instruction hashes remain unchanged. Actual desktop loader/tool availability, RTK bridge automatic rewrite, visible `windowsHide`, and restart/resume have not been accepted. Raw hook JSON acceptance is not proof that the host actually invokes that hook.
- Real-workload end-to-end tail-latency improvement has not been measured. The small free synthetic fixture establishes behavior and timing only for that fixture.

## Deployment and CI

The installation was **not switched**; deployment backup/restore and post-switch checks were therefore not executed or claimed. The existing plugin and RTK remain in place. Any later switch needs a full preserved installation/native/config manifest with hashes, an actual restore check, quiescence of old repair processes, and acceptance of the failed orphan/installer boundaries. An active Codex restart or interruption of another task requires explicit interruption authorization; none was performed here.

The same remote `codex_windows_latency_candidate` branch is updated only by fast-forward. No force push, main changes, PR, workflow alteration or paid model A/B is part of this work. CI push filters are `[main, next]`; absence of runs/checks for this candidate is **not** a pass. Read final SHA/tree and exact-head run counts from the publication evidence.

Context characters avoided, byte metrics and RTK gain figures do not establish reduced total billing. Current technical recommendation remains: retain RTK for explicit supported calls, retain Context Mode for on-demand indexing/search, and do not deploy this experimental replacement yet.
